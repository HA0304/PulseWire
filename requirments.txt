# PulseWire — Autonomous 90-Minute Engineering Sprint

You are a senior Python systems engineer and autonomous coding agent working inside VS Code with GitHub Copilot Agent Mode.

Your objective is to build **PulseWire**, a functional, deterministic, discrete-event packet network simulator, from scratch within a 90-minute development sprint.

You must implement, test, debug, document, and commit the project incrementally. Do not merely generate source files. Execute the code and verify its behavior.

## 1. Technology Stack

- Python 3.12+
- Python standard library `heapq` for event scheduling
- `pytest` for automated testing
- Streamlit for the interactive dashboard
- Git and GitHub CLI for version control
- GitHub Actions for continuous integration

Avoid databases, authentication, Docker, Kubernetes, cloud infrastructure, and unnecessary frameworks.

## 2. Core Simulator Requirements

Implement the following:

**Packet model**
- Unique packet ID
- Source and destination
- Packet size in bytes
- Creation timestamp
- Transmission, delivery, and acknowledgment timestamps
- Packet status

**Discrete-event engine**
- Priority queue using `heapq`
- Events ordered by `(simulation_time, sequence_number)`
- Deterministic ordering for simultaneous events
- Event types: `PACKET_ARRIVAL`, `TRANSMISSION_COMPLETE`, `PACKET_DELIVERED`, and `ACK_ARRIVAL`
- Simulated clock, without real sleeps or threads
- Event trace suitable for visualization and debugging

**Network simulation**
- Configurable link bandwidth in Mbps
- Propagation delay in milliseconds
- Finite FIFO packet buffer
- Drop-tail queue management
- Packet generation rate
- Configurable packet sizes
- Random packet loss probability
- Fixed random seed for reproducibility
- Link serialization: only one packet can transmit at a time
- Correct queueing, transmission, and propagation delays
- Simplified acknowledgment mechanism for RTT calculation
- Clear distinction between queue drops and random channel losses

Use:

`transmission_delay_seconds = packet_size_bytes * 8 / (bandwidth_mbps * 1_000_000)`

Define RTT explicitly, including acknowledgment assumptions. Do not implement TCP congestion control.

## 3. Metrics and Acceptance Tests

Calculate:

- Total packets generated
- Packets successfully delivered
- Packets dropped due to queue overflow
- Packets lost due to random channel loss
- Delivery ratio
- Throughput in Mbps
- Average one-way latency
- Average RTT
- Queue occupancy over simulated time

Write automated tests for:

1. Correct event ordering and tie-breaking.
2. Correct transmission delay.
3. Correct serialization of multiple packets.
4. No packet loss under sufficiently low traffic.
5. Queue overflow under high traffic.
6. Complete loss when channel loss probability is 100%.
7. Identical results using the same random seed.
8. Invalid configuration rejection.
9. Correct RTT for a deterministic single-packet example.
10. Packet conservation: generated packets must equal delivered, dropped, lost, or still in flight/queued.

Use analytically calculated expected results for at least one test. Do not make tests pass by hardcoding expected outputs in production code.
